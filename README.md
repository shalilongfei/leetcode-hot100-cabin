## 这是什么

一个**纯前端、零运行时依赖**的力扣 Hot 100 复习工作台。

市面上刷题工具多数只给你题目和答案。这个不一样：它把每道题的**执行过程**拆成了帧——像调试器一样，一行一行走，每走一步都能看到变量怎么变、指针在哪、递归栈堆到第几层。

```
┌──────────────────────────────────────────────────────────┐
│  SECTION 67 / 二分查找                                    │
│  寻找旋转排序数组中的最小值                                │
│  中等 · O(log n) · O(1) · 热度 ★★★★★                      │
├──────────────────────────────────────────────────────────┤
│  一句话本质                                               │
│  把 nums[mid] 和右端比较：小于右端说明最小值在左半（含 mid）│
├──────────────────────────────────────────────────────────┤
│  思路解剖                                                 │
│  01 闭区间   lo, hi = 0, n-1，while lo < hi               │
│  02 收缩     nums[mid] < nums[hi] → hi = mid；否则 lo=mid+1│
│  03 答案     nums[lo]                                     │
├──────────────────────────────────────────────────────────┤
│  C++ 代码（点击任意行 → 可视化跳到那一帧）                  │
│  ┌────────────────────┬─────────────────────────────────┐│
│  │ 1  class Solution  │  输入 nums = [3,4,5,1,2]         ││
│  │ 2  public:         │                                 ││
│  │ 3   int findMin(…  │  lo=0  hi=4  mid=2              ││
│  │ 4    int lo = 0…   │  nums[mid]=5  nums[hi]=2        ││
│  │ ●5    while (lo<hi)│  → 5 > 2，走右半，lo = mid+1    ││
│  │ 6      int mid=…   │                                 ││
│  │ …                  │  ◀ ▶ 播放  3 / 13               ││
│  └────────────────────┴─────────────────────────────────┘│
├──────────────────────────────────────────────────────────┤
│  变量快照  lo=3  hi=4  mid=3                              │
└──────────────────────────────────────────────────────────┘
```

**每一帧都带三样东西**：当前执行到哪一行、这一行执行完之后的全部局部变量、一句人话解说。

## 打开方式

### 方式一：双击 `Hot100.exe`（推荐，免装任何东西）

仓库已含打包好的 onedir 版本：

```
Hot100.exe          ← 双击这个
_internal\          ← 运行库，必须在同一目录
assets\  css\  js\  ← 网页文件，exe 启动时读这里
```

启动后右下角出现托盘图标，浏览器自动打开页面。**没有黑框窗口。**

- 左键托盘图标 = 打开页面
- 右键 = 菜单（打开 / 重启 / 退出）
- 再次双击 exe 不会起第二个服务，只会把页面拉出来
- **只有从托盘"退出"才会停服务**，关掉浏览器不影响

> 为什么是 onedir 而不是单文件？PyInstaller 的 `--onefile` 引导程序要往 `%TEMP%` 解包出 `_MEIxxxxxx` 目录，在部分 Windows 11 构建（24H2 / 25H2）上会直接报 `Could not create temporary directory!` 弹错退出。onedir 不解包，稳定得多。代价是 `_internal\`（54MB）必须和 exe 放一起。

### 方式二：双击 `start.bat`（源码模式，需要 Python）

```bat
start.bat
```

起一个本地静态服务并打开 `http://127.0.0.1:8791/`。脚本会自动找 `python` 或 `py -3`，找不到会提示去装。

用本地服务而不是 `file://` 的好处：`localStorage` 更稳（某些浏览器对 `file://` 的存储有限制），且改了代码刷新就生效。

### 方式三：直接双击 `index.html`

纯静态，`file://` 也能跑。功能完整，只是进度存储可能不如方式一稳。

## 核心：代码 ⇄ 可视化联动

学习页中间是一块**双栏面板**：左边代码，右边可视化，两边是通的。

### 三个方向的联动

| 你做什么 | 发生什么 |
|---|---|
| **点任意一行代码** | 可视化跳到最接近的那一帧；该行没有对应帧时，跳到最近的下一帧 |
| **播放可视化** | 代码自动高亮当前执行行，并滚动到视野内 |
| **拖动进度条 / 单步** | 代码高亮同步跟随 |

代码按行渲染，行号右侧有**小圆点**的行表示「这行有对应的动画步骤」——一眼能看出哪些行是真正在执行逻辑。

### 控制条

播放 · 暂停 · 上一步 · 下一步 · 重置 · 0.6–2x 变速 · 拖动进度，步数实时显示 `3 / 13`。

### 专注模式

- 按 `[` 或点左上 `☰` —— **收起题库**
- 按 `]` 或点右上 `▥` —— **收起右栏**
- 两侧都收起时，代码区宽 712px、字号自动到 15px

切换 C++ / Python 或进入挖空模式时，行映射会自动重建。

## 这不是按行号猜的

这是整个项目花时间最多的地方。

很多可视化工具是"按行号猜"：给个步骤数，除以行数，估一个大概位置。那种动画看着像模像样，但一遇到循环就露馅——它不知道这一轮走的是哪个分支。

**这里的做法是把代码的执行过程真的写成了帧。** 每一行代码执行时推一帧，帧里带着那一行执行完之后的**全部状态**：局部变量、数组内容、指针位置、矩阵、链表节点、递归调用栈。

于是循环会一圈一圈重复经过同一批行——**行号真的会回绕**；递归会一次一次压栈出栈。

### 三层结构

```
js/viz/exact*.js    ← 编译器级帧表：每题一张「解说 → 行号」数组
        ↓              按顺序匹配，第一个命中即定案；一条都不中就沿用上一帧，不做任何推断
js/viz/linefix.js   ← 行号对齐器：解说词判出这一步是「空判断/累加/递归/回溯/自增/取极值」
        ↓              锚到对应代码行；没有锚点的帧顺着可执行行往下走一步
js/viz/dbg*.js      ← 执行轨迹：100 题共 2730 帧的逐帧数据
```

**全站 3582 帧零推断**——每帧的行号都来自查表。

### 真实数据

| 指标 | 数值 |
|---|---|
| 总帧数 | **3853 帧** |
| 循环回绕 | **869 次** |
| 覆盖题目 | **100 / 100** |

几个例子：

- **42 接雨水** 58 帧：`4 → 5 → 6 → 7 → 8 → 9 → 10 → 6 → 7 → 12 → 13 → 14 → 6`——初始化 → while → if → lmax → ans → ++l → 回 while → if（这轮走右分支）→ rmax → ans → --r
- **437 路径总和 III** 141 帧：进 dfs 后一直在函数体里跳，`cnt` 哈希表和 `cur` 逐帧变化，右侧递归栈一层层压上去再弹回来
- **46 全排列** 205 帧、回绕 25 次：右侧能看到 `bt() / bt(1) / bt(1,2)` 调用栈一层层压上去再弹下来
- **48 旋转图像** 18 帧：`n=3 → i=0 → j=1 → swap(0,1) → j=2 → swap(0,2) → i=1 …`，矩阵每帧都在变
- **322 零钱兑换** 41 帧，两层循环各自回绕

行号与 `js/data/cpp1~3.js` 的 C++ 模板严格对齐，脚本校过：没有越界、没有落在空行。切 Python 时行号按比例换算，不保证逐行。

### 递归进出（调用栈可视化）

21 道递归 / 回溯题的每一层调用都留了完整帧：**进入（压栈）→ 计算 → 递归子调用 → 子调用返回 → 回溯撤销 → return（弹栈，值回传父级）**。

右侧多一排调用栈胶囊，每层显示 `函数(参数) ‹当前累计返回值›`：

- **青色高亮** = 正在执行的那一层
- **绿色** = 已经算完、即将返回的层
- 栈越往右越深

以 437 路径总和 III 为例：

```
pathSum(root,8)
dfs(10,0)‹0›              ← 进 A，cur=10，res=0
dfs(5,10)‹0›              ← 进 B，cur=15
dfs(3,15)‹1›              ← 进 D，命中 1 条（D 自己）
dfs(3,18)‹0›              ← 进 G，两个空孩子都返 0
```

每一帧都能看到 `cur` 怎么累加、`cnt` 前缀表怎么增删、返回值怎么一层层往上合并。

## 变量快照（调试器 Local 面板）

每一帧都挂着当时的全部局部变量，显示在可视化下方：

```
l=1  r=11  lmax=0  rmax=1  ans=0
```

取值优先级（前面准，后面兜底）：

1. 帧里显式写死的 `vars`
2. `ptr` 字段（双指针下标）→ `l=1, r=11`
3. `listPtr` 字段（链表指针名 → 节点下标）→ `head=0, prev=0`
4. `gridHi` 字段（矩阵坐标）→ `i=2, j=1`
5. 解说文本解析 → `cur += 5 → 15` 得到 `cur=15`

变量名从 C++ 模板里抽（含 `ListNode` / `TreeNode` 指针、`for` 循环、结构化绑定 `auto& [v, f]`），随帧累积。

### 变量不会提前出现

`int l = 0, r = n - 1` 这行没执行到时，面板里就没有 `l` 和 `r`；执行到了才冒出来，之后每次赋值都刷新。

**这是真实调试器的行为，不剧透后面的结果。** 所以变量面板是「随执行生长」的，不是一开始就摆满：

```
帧 0   L4  （还没变量）
帧 2   L7  node=5  lo=-∞  hi=+∞  栈深=1
帧 3   L9  node=5  lo=-∞  hi=+∞  栈深=1  ok=true
帧 4   L7  node=1  lo=-∞  hi=5   栈深=2
```

全站 3853 帧里 **99% 带变量**，剩下的帧确实是「这一步还没有标量变量」的情况（比如函数入口、纯 return）。

## 六层审核（全部归零）

数据量大就一定会写错。这个项目用六个互相独立的脚本交叉验证，每一层查的东西都不一样。

| # | 审核 | 查什么 | 结果 |
|---|---|---|---|
| 1 | **结构** `_audit.js` | 行号越界、落在空行、无理由跳行、重复帧、帧数过少、空解说 | **100/100 通过，问题 0** |
| 2 | **语义** `_audit2.js` | 解说写 `swap`/`push_back`/`return`/`while`，那行必须真的有这个记号 | **不符 0** |
| 3 | **行覆盖** `_audit3.js` | 每一条可执行语句至少有一帧落到 | **0 题未覆盖** |
| 4 | **算术** `_arith.js` | 解说里 `max(0,0)=0` / `6-1=5` 这类算式重算一遍 | **100 个算式，算错 0** |
| 5 | **答案对账** `_verify.js` | 每题独立写一遍算法，和 trace 最终答案比 | **100/100 一致** |
| 6 | **解说↔面板** `_consist.js` | 解说写 `x = 3`，变量面板的 x 也得是 3 | **891 处，不一致 0** |

跑法：

```bash
node _audit.js      # 结构
node _audit2.js     # 语义
node _audit3.js     # 行覆盖
node _arith.js      # 算术
node _verify.js     # 答案对账（100 题独立实现）
node _consist.js    # 解说↔面板
node _replay.js     # 逐帧全变量对比
node _final.js      # 逐帧归零总检
node _delta.js      # 变量滞后 / 凭空变化 / 残留
node _blank_audit.js  # 挖空规格
node _blank_leak.js   # 挖空是否泄漏答案
```

全部零依赖，`node xxx.js` 直接跑，不需要 `npm install`。

### 第 5 层抓出的三个真 bug

`_v1~v4.js` 里为 100 道题各写了一份**完全独立**的实现（不复用 trace 的任何逻辑），只吃相同的输入，算出答案后对账。这层抓到：

1. **153 寻找旋转排序数组最小值** —— 循环条件写成了 `lo <= hi`（代码是 `lo < hi`），`[3,4,5,1,2]` 最后返回 2，正确答案是 1
2. **438 找到所有字母异位词** —— 窗口频次表比较时没过滤值为 0 的键，漏掉索引 6，只输出 `[0]`，正确答案 `[0,6]`
3. **208 实现 Trie** —— trace 只处理了 `search`，漏了 `startsWith` 这一支

第 6 层抓出两个：139 的补帧把 `maxLen` 落成 0（解说写的是 4）；138 的解说用 `p = 7` 描述"节点值"，和面板里表示下标的 `p` 撞了语义。

### 逐题人工审查

从第 1 题到第 100 题逐帧过了一遍（每题看入口帧、循环帧、分支帧、收尾帧）。修掉的实质问题节选：

| 题 | 问题 | 修法 |
|---|---|---|
| 160 相交链表 | 模拟成"两指针同步递增"，结果返回 null（实际交点 8） | 重写为走完一条链切到另一条的头，第 8 步相遇 |
| 189 轮转数组 | 解说写「k %= n → 3」，被解析成 n=3 | 改成「k 取 3」，n 全程稳定 7 |
| 238 除自身乘积 | 后缀积那段的「阶段」标签一直显示前缀积 | 三帧都带 `阶段: "后缀积"` |
| 279 完全平方数 | `i = N` 落在 `dp[0] = 0` 那行 | 行号 5→6 |
| 79 单词搜索 | 找到时末帧仍指向 `return false` | 按 found 分流到 L7 / L8 |
| 155 最小栈 | getMin 帧的栈内容是上一帧的 | 每帧带当前 `栈` 与 `最小值` |
| 54 螺旋矩阵 | 四条边的 push 全被映射到 L9 | note 加「上边/右边/下边/左边」分别对应 L9/L11/L14/L18 |
| 234 回文链表 | 反转后半段的整个循环没有帧 | 重写，三段循环逐行 |
| 199 右视图 | 缺队列初始化、层循环、右孩子入队 | 重写，27 帧覆盖 L4–L16 |
| 114 展开链表 | 缺 left/right/tail 三个中间量 | 重写，87 帧 |
| 148 排序链表 | 缺快慢指针循环、merge 的取小分支 | 重写，58 帧 |
| 25 K 组翻转 | 缺 L6（kth 复位）与 L11（区间 while） | 重写，44 帧 |
| 146 LRU | 缺命中更新与淘汰三步 | 重写，23 帧 |
| 105 构造二叉树 | leftLen 变量比解说慢一帧 | 帧里显式带 `leftLen` / `mid` |

### 行覆盖这一层最后怎么清零的

1. 先排除「本就不该有独立帧」的行——跨行函数签名的续行、结构体成员、无初始化的纯声明；
2. 再排除「数据没走到的条件分支」——比如 15 的去重 while 要相邻元素重复才进，当前数据不重复；这类行它前面的分支已经有帧，说明控制流走到了，只是这一支没触发；
3. 剩下的真语句逐题补帧：
   - **函数开头的初始化**（`int m = ..., int best = 0`）由 `headfix.js` 插在第一步之前，位置绝不会错；
   - **循环体 / 分支体内的行**在各题 trace 里手工加，每轮一帧。

> **中途试过写脚本按行号自动补，结果把 146 的「不存在」分支塞进了「更新已存在」的三行、把 84 的 `height`/`left` 塞到 `while` 根本没执行的那一轮——那是造假，脚本已删除。**
>
> 现在的原则是：**位置不确定就不补，宁可承认这一支没被数据触发**（比如 146 的重复 `put`、15 的相邻去重、101 的一空一非空）。审计也会把这类行判为「未触发的分支」而不是「漏帧」。

## 四个模式

### 学习

逐题看：本质 → 思路 → 模板 → 逐帧可视化。`←` `→` 切题，空格播放，`D` 挖空，`L` 换语言。

**题目按钮**（hero 右上，黄色书本图标）弹出摘要卡：输入示例、一句话本质、需要做到的几步、边界与坑、复杂度，底部一键跳力扣原题。`Esc` 或点遮罩关闭。

### 复习

间隔重复队列。卡片翻面看本质与三步要点，四档自评——`忘了` 的那张 10 分钟后就回来。

### 抽考

选范围和题量，闭卷回忆 + 计时，答完出成绩单。

### 看板

## 代码模板与挖空

- **默认 C++**，右上角切 `Python3`，选择记在本地
- 100 题全部有 C++ 实现（`js/data/cpp1~3.js`），`class Solution` 形式，可直接粘去提交
- 链表 / 二叉树 / 随机链表 / LRU / Trie 的题目会把 `struct ListNode`、`class TreeNode`、`class Node` 等定义**补在代码上方**（可折叠），本地读代码不用再翻题面；提交时无需重复定义
- 可视化面板顶部常驻一行 `输入`，把该题的输入（数组、target、矩阵、层序树、链表）按原样写出来
- **挖空**在当前语言的代码里挖 3 个关键标识符，回车校验；`_blank_leak.js` 专门检查挖空有没有泄漏答案
- **复制** 复制全文

## 技术栈

| 项 | 选择 | 为什么 |
|---|---|---|
| 前端 | 原生 JS + CSS，无框架 | 零构建、零依赖，双击就能跑 |
| 语法高亮 | 手写（`js/highlight.js`） | 只要 C++ 和 Python，上 Prism 反而更重 |
| 图标 | 手写 SVG 路径（`js/icons.js`） | 不引 icon font，不闪 |
| 动画 | DOM + CSS transform | 帧是离散状态，不需要 canvas |
| 存储 | `localStorage` + JSON 导入导出 | 不做后端，隐私留在本地 |
| 打包 | PyInstaller onedir + pystray | 只为了让非技术用户双击即用 |

- 只保留顶栏一条模糊
- 切题不再重建 100 行侧栏、不重绘吉祥物 SVG、不重建右栏（签名比对），侧栏只改选中态
- 列表项加 `contain: layout` 限制重排范围

```

跑审计（**需要 Node，不需要 npm install**）：

```

审计脚本通过 `_lib/load.js` 定位仓库内的 JS，**不依赖任何绝对路径**——clone 到任何目录都能直接跑。

## 打包成 exe

```bat
build.bat
```

做三件事：

1. 装 `pystray pillow pyinstaller`
2. 从 `assets/whale-girl-face.png` 生成多尺寸 `assets/hot100.ico`
3. `PyInstaller --onedir` 打包，再把产物并回项目根目录

打包完直接双击 `Hot100.exe`。

### 一个已知的 Windows 11 兼容性修补

`tray_server.py` 里有一段 `_tolerate_pystray_filter()`：pystray 建好托盘窗口后会调 `ChangeWindowMessageFilterEx` 去允许收到 `WM_TASKBARCREATED`，这在部分 Windows 11 构建（如 25H2）上会以 `WinError 5` 失败，而 pystray 的 errcheck 会直接抛异常，结果**托盘图标根本起不来**。

这里把 `ERROR_ACCESS_DENIED` 容错掉：顶多收不到任务栏重建消息，托盘本身照常工作。
